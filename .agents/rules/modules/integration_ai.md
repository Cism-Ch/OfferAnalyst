# 🌐 Module : Intégration AI, Télémetrie & Workflow
> Règles procédurales relatives à OpenRouter, typage TypeScript strict et conventions globales.

- [R-INT-01] Bannir strictement `any`. Définir des interfaces TypeScript explicites ou inférer les types via `z.infer<typeof Schema>`.
- [R-INT-02] Toujours importer les modules via l'alias `@/*` et supprimer les imports inutilisés pour maintenir un code propre et éviter les avertissements ESLint.
- [R-INT-03] Middleware Routing : Ne jamais utiliser `pathname.startsWith(route)` avec la route racine `'/'` dans une liste de routes publiques (cela valide aveuglément toutes les requêtes). Utiliser `pathname === route`.
- [R-INT-04] FinOps & Télémétrie AI : Interroger `GET https://openrouter.ai/api/v1/auth/key` pour auditer le statut, solde $ et limites d'une clé sans coût d'inférence. Avec `@openrouter/sdk`, les métriques d'usage sont strictement en camelCase (`promptTokens`, `completionTokens`, `totalTokens`).
- [R-INT-05] Décision Décodage Contraint LLM : Quand `responseFormat: { type: "json_object" }` est utilisé, l'instruction système DOIT exiger un objet JSON `{ "offers": [ ... ] }` et non un tableau brut `[ ... ]` (interdit par la grammaire BNF contrainte).
- [R-INT-06] Extracteur Universel LLM : Dépiler les réponses AI via `extractOffersArray()` pour absorber les tableaux directs, clés conteneurs (`offers`, `data`, `results`), dictionnaires ou objet unique sans crash Zod.
- [R-INT-07] Continuité Hybride Guest / Cloud (BYOK & Onboarding) : En mode Invité (`!session?.user`), sauvegarder les clés saisies en onboarding dans `useTemporaryApiKeys` (avec mise à jour fonctionnelle `setKeys(prev => ...)` anti-race-condition) et propager `tempKeys.getKey('openrouter')` vers toutes les Server Actions IA (V1 & V2) via le résolveur hybride `getAPIKey()`.
- [R-INT-08] Historique Hybride (TTL 7j Local vs Rétention Cloud 90j) : Stocker l'historique invité dans `localStorage` avec expiration à 7 jours, migrer et dédupliquer automatiquement vers MongoDB à la connexion (`migrateGuestSearchesAction`), et purger via CRON (`/api/cron/cleanup-history`) les entrées non épinglées > 90 jours en préservant `isPinned: true`.
- [R-INT-09] Export & Partage Collaboratif : Neutraliser l'injection CSV (CWE-1236) en préfixant les cellules débutant par '=,+,-,@' d'une apostrophe. Translitérer l'Euro en EUR et borner les justifications à 12 lignes en génération PDF-1.4 pour interdire les coordonnées négatives. Protéger les liens (/share) contre l'IDOR (accès ObjectId restreint au propriétaire) et utiliser incrementView: false pour la génération de métadonnées RSC.
- [R-INT-10] Versioning Sémantique Adaptatif RSI (vX.X.X-MENTION) : Tout incrément de version doit être évalué par le moteur SemVer RSI (`version_manager.py`) à partir du contexte Git et du Changelog. Le format standardisé `vX.X.X-MENTION` (ex: `v1.1.1-patch`, `v1.2.0-mobile-ui`) doit être synchronisé dans `package.json`, scellé sous `## [Unreleased]` dans `CHANGELOG.md` et annoté par un tag Git via `pnpm run rsi:bump`.
- [R-INT-11] Navigation Cookie Anti-Bounce (SaaS Vitrine vs App) : Pour basculer entre une vitrine SaaS et le dashboard applicatif, persister le mode dans un cookie ('offeranalyst_app_mode'). L'accès aux sous-routes applicatives ou l'action d'entrée doit fixer ce cookie ('app') afin qu'un rafraîchissement (F5) ou un retour sur '/' ne renvoie jamais l'utilisateur actif vers la vitrine marketing, tout en maintenant l'accès explicite via '/landing' ou '?view=vitrine'.
- [R-INT-12] Économie de Contexte & Attente Passive Asynchrone : Ne pas lancer 'eval:quick', de tests lourds ou de builds à chaque micro-édition ; réserver la validation complète à la clôture de tâche avant commit ou après un refactoring transversal. Lors de l'exécution d'une commande asynchrone (evals, Playwright, build), proscrire tout polling répétitif ('manage_task status') et privilégier l'attente passive (réveil réactif du système) afin d'éviter la saturation de la fenêtre de contexte.
- [R-INT-13] Action & Monétisation Post-Scoring (OpenRouter SDK chatRequest) : Dans @openrouter/sdk, l'appel à openrouter.chat.send() requiert impérativement l'encapsulation { chatRequest: { model, messages, temperature, maxTokens } } (et non les champs au premier niveau). Pour les modaux de livrables (négociation, candidature), synchroniser le chargement avec useEffect et cleanup (isSubscribed) sans appeler de setState synchrone dans le corps de l'effet afin de respecter les règles strictes de React 19 et react-hooks/set-state-in-effect.
